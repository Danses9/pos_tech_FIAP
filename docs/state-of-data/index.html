Como foi feito

Um data lake em camadas

Cada job lê uma camada, trata e grava em Parquet na seguinte. O dado bruto nunca é alterado.

Raw

Os 3 CSVs da pesquisa, como vieram.

Cleansed

Nomes de colunas, encoding, vazios e duplicados.

Transformed

Um schema único para os três anos.

Curated

Tabelas agregadas, uma por pergunta.

Glue Crawler→ Data Catalog→ Athena (SQL)→ Python · pandas · matplotlib
O que os dados mostraram

Três achados

A AWS passou a Azure

Em 2023 a Azure liderava. Em 2025, quase metade dos profissionais usa AWS.

A IA Generativa entrou na pauta

20,8% → 6,6%

Caiu para 6,6% a parcela de empresas em que IA Generativa não é prioridade (2023 → 2025).

O gargalo da IA é gente e dado pronto

Falta de expertise38,8%
Dados não prontos36,8%
ROI não comprovado32,8%

As barreiras mais citadas em 2025, e as que mais cresceram desde 2023.

O que eu levo deste módulo

Meus aprendizados

  • Arquitetura em camadas

    Cada camada com uma responsabilidade, mantendo a origem de cada dado rastreável.

  • Dado real é bagunçado

    Encoding quebrado, colunas que mudam de tipo entre anos e erros de digitação nas faixas salariais.

  • ETL na nuvem

    Jobs em PySpark no AWS Glue, catálogo com Crawler e consultas SQL no Athena.

  • O que o dado não diz

    Olhar a base de respostas, não confundir amostra com mercado nem correlação com causa.
